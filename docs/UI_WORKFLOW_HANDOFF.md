# FlashCards Android UI and workflow handoff

Implement this in the existing Kotlin Compose app. Read AGENTS.md first. Use source inspection and Git only for this pass. Commit each coherent change. App launches, builds, emulators and test runs require separate authorization. This plan comes from source inspection. Device behavior, deployed service health and visual rendering are unverified.

## Destination map

| Entry | Destination and primary action | Back or success |
|---|---|---|
| Signed-in launch | Your decks. One search field, active deck rows, one accessible Add deck button. Each row opens the deck. | Preserve the query and scroll position when returning. |
| Add deck | Material 3 bottom sheet with exactly two choices, Create manually and Create with AI. | Dismiss returns to the same list. Selecting either closes the sheet before navigation. |
| Create manually | A screen with title, optional description and language defaults under More options. Save once. | Open the saved deck with Add card visible. Cancel creates nothing. |
| Create with AI | Full-screen conversation with a topic/notes prompt, message history, inline proposal review and a composer above the keyboard. | Back returns to decks. Successful creation replaces the conversation route with the new deck. |
| Existing deck | Title, cards, Add card and Study. Use a labeled overflow item, Ask AI about this deck, for questions or proposed edits. Put deck management and secondary card actions in menus. | Back returns to decks. |
| Ask AI about this deck | Standalone chat scoped to the saved deck. Explain-only answers appear directly. Proposed edits require approval. | Back returns to the same deck. Approving an edit keeps the conversation open. |
| Study | Open a dedicated session directly using practice, term first, all eligible cards and shuffle by default. Offer Study options in the deck menu for other modes and filters. | Resume an unfinished session for this deck or explicitly start another. Exit returns to its caller. |

Remove global bottom tabs and the wide-screen rail from this workflow. Use one route-specific app bar. A compact overflow on the library app bar can reach Study history (including cross-deck review), Reminders, Archived decks and Settings. These preserve existing workflows without adding home sections. Keep the same destinations on wide screens, constrain reading width, and keep Back behavior identical. Show loading, offline or retry feedback where it explains the current action.

## Source findings and fixes in implementation order

1. **Replace the nested navigation.** Start in `FlashApp.kt`, symbols `FlashApp`, `DecksScreen`, `DeckScreen`. Today HomeRoute switches on a separate tab string and DeckRoute has a chat flag. AI creates a random deck ID and opens the tabbed DeckScreen. Even opening a real deck before metadata arrives can select Chat permanently because the initial tab depends on a missing deck. Keep the current Navigation 3 stack. Introduce explicit serializable keys for manual creation, AI creation and existing-deck chat. Keep DeckRoute for cards and SessionRoute for studying. Allocate IDs on the navigation event, save them across recreation, and distinguish loading, unavailable and deleted decks from new AI drafts. Replace the manual creation route on successful save. Tie async navigation to the initiating route and signed-in user so a late callback cannot push a screen after Back. Clear user-scoped routes and sheet state on sign-out.

2. **Simplify the library and secondary screens.** In DecksScreen remove row buttons, sorting chips, archive toggles, slogans, draft rows and session banners. Keep recent ordering and case-insensitive title search. Show separate loading, empty-library and no-search-results states. Never show zero cards from an incomplete cache. In DeckScreen remove the tab row, download/update, import and CSV/TSV actions. Remove download management, AI budget, billing, backend diagnostics and file-import/restore entry points from visible settings. Remove obsolete callbacks from MainActivity and previews where unused. Keep appearance, speech, account controls and recovery for trashed content reachable in secondary screens. Keep existing stored records, server-side budget enforcement and private diagnostics. Audit sign-in, empty states, operation errors and dialogs for references to removed controls. Use specific user actions such as “Reconnect to open this deck.”

3. **Make deck loading a prerequisite the app handles.** Inspect `FlashRepository.download`, `refresh`, `saveDeck`, `saveCard` and `FlashViewModel.startSession`. Cards are paged into Room and a downloads marker is committed with the complete set. Study currently disables setup without that marker. Multi-deck review can fail the entire selection on the same check. Add one account- and deck-scoped preparation path shared by opening a deck and starting study. Read a complete cached deck immediately, refresh it in the background when online, and fetch an uncached deck before showing cards. Coalesce simultaneous requests for the same deck. Preserve the last complete copy on failure. For an uncached offline deck, show a connection message with Retry. For an empty loaded deck, show Add card. Neither case should open an empty session.

   Resolve multi-deck and reminder selection to eligible active deck IDs before preparation. Keep the existing semantics for selecting all active decks. If part of a selection is unavailable, identify the affected decks and allow retry or an explicit selection change. After a successful fetch, create the session from the committed cards and progress for the same user. Reading state.value immediately after the Room transaction can still return the previous list. Continue using StudyEngine and persistSession, including their size limits and revision guards.

4. **Separate saving from refreshing.** Current manual saves call mutateContent and then download before signaling success. AI confirm applies the proposal, records its terminal state, then downloads. If that download fails, refresh only retries decks with an existing downloads marker, which a new deck may lack. Record the successful mutation and target deck ID independently of content loading. Navigate once after confirmed creation and let the destination retry loading that exact ID. Retry only the read after a known successful write. On an unknown write outcome, reconcile the original operation before sending another. Apply the same rule to a new card, and keep its ID stable across recomposition and retry. Manual creation must land in the deck even if the cards need a later refresh.

5. **Make AI chat recoverable.** Reuse ChatScreen, the persisted ChatRequest, turns and proposals, and the existing send/recover/confirm calls. Give creation and existing-deck chat distinct prompts. Bind each route to one stable conversation ID. Keep a single composer and move history/new conversation into a secondary action. Existing home draft recovery relies solely on local chat requests. Inside the creation screen offer a small resume action for unfinished drafts identified from saved conversations and requests scoped to the signed-in user. A draft must be reachable after Back or process recreation without creating a deck row. Keep pending requests visible and recover with the same request ID. Surface a failed send inline with editable message text. Keep raw request IDs out of the normal conversation. Track expanded proposal previews by proposal ID (the current shared details flag expands every preview). Render readable card fronts/backs and changed fields. Expiration, rejection and plain answers leave the conversation usable. Only approval of a create-deck operation may trigger creation navigation. Never infer approval from a reply or deck-list timing.

6. **Finish the study and editor flows.** Route deck Study, customized setup, history resume and reminder taps into the same session screen. Use one exit affordance (currently Close and Save & exit both call onExit). Keep rating gated on reveal, preserve undo, and restore the same session ID and cursor after exit. Make Browse completion explicit: its current Next button disables at the last card and advance hardcodes finished=false, so it stays unfinished. Offer Finish at the last card, persist completion and render a browse summary without quiz grades. Keep practice, typed, multiple-choice and test completion rules distinct. Show a useful no-match state with Change filters when a filter excludes every card. For card edits, keep the form open on failure, prevent double saves and restore the edited card or list position after success.
